How decern establishes a caller

decern will not start until the deployment names how its callers are established. The five postures differ in how the caller is proven, and that also decides whom the caller may name and what the record says about it. From the kernel on, every request takes the same path: the solver-proven kernel, the recorded decision, the fail-closed serve. Pick a posture and step the request through it.

Grounded in the standards registry the code is held to. Steps and section citations come from decern's own conformance records for RFC 9068, RFC 9421, SPIFFE JWT-SVID and draft-hardt-oauth-aauth-protocol-11. Verification only — decern issues no tokens. This is an explainer; read the code for the exact behaviour.
