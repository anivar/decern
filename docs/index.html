Two guarantees

Proof over promises.

Most authorization layers assert their safety and test a few examples. decern proves it, and records it.

Proven, not tested

Machine-checked over every input

The decision is a pure function of (principal, authority graph, policy, now). Nine safety invariants over that function are discharged across the entire input space by the cvc5 SMT solver — a green proof means the kernel can't violate them on any input, not just the ones in a test file.

Verifiable, not trusted

A tamper-evident ledger

Every decision lands in an append-only, Ed25519-signed, hash-chained ledger. A signature proves each record authentic; the chain proves nothing was dropped. Anyone can verify it offline — without trusting the operator who produced it.

What is proven

Nine invariants, over the whole input space.

Each statement is calibrated to exactly what the solver certifies — a proof never claims more than the machine verified. Each ships with a negative control that fails if the guarantee is removed.

money-gate
No privileged money action without explicit approval.
isolation
No decision ever crosses a tenant boundary.
decay
Nothing allowed once authority has expired.
attenuation-edge
No access without ownership, a delegation ancestor, or an explicit grant.
scope-gate
Bounded actions require their named scope.
revocation-gate
A revoked principal is allowed nothing.
residency-gate
Residency-labeled resources need matching clearance.
role-gate
Role-required resources need the role.
consent-gate
Non-owned PII needs explicit consent.

How it works

Decide. Record. Or refuse.

A thin, fail-closed PDP: a decision is served only if its audit record was written first.

01
Evaluate
The proven kernel decides over the authority graph. The server owns the clock.
02
Record
The decision + a derived accountable-owner are appended, signed, to the ledger.
03
Serve or 503
Returned only if the record was written — never a bare allow.
04
Verify
decern verify re-checks the chain and every signature, offline.

Quickstart

Prove it, run it, verify it.

# 1. Prove all invariants hold over every input (cvc5)
cargo run -p decern-cli -- prove

# 2. Run the fail-closed PDP (writes a tamper-evident ledger)
cargo run -p decern-server -- --ledger /tmp/decern.jsonl &

# 3. Decide over HTTP (AuthZEN-shaped)
curl -s localhost:8080/access/v1/evaluation -d '{
  "subject":{"type":"Principal","id":"corp"},
  "action":{"name":"Read"},"resource":{"type":"Resource","id":"claim1"}}'

# 4. Verify the ledger — chain + every signature
cargo run -p decern-cli -- verify --ledger /tmp/decern.jsonl

There's also an approval-backed, provably-attenuated Mission — a scoped, bounded authority that can neither out-scope nor outlive the approver who granted it, with every transition recorded to the same ledger.

What "proven" means here

cvc5 proves the kernel's invariants over every input — that delegation can only narrow, that a revoked principal is denied, and the rest. It does not prove that your Cedar policy expresses what you intended. The guarantee is about the mechanism, never a claim that a given deployment is "secure." That line is the whole point — decern is careful not to cross it.
