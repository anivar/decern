Standards conformance

What decern implements, and what it does not

decern is held to the specifications it touches by a standards registry in the repository, which records, for each spec, what the text requires, what decern does, and when the text was last read. This is the honest map drawn from it. The amber column is the part a product page usually hides: where decern deviates, and why. The full, dated record is in the registry.

The decision API, and contestability

AuthZEN 1.0OpenID The authorization surface: single and batch evaluation, subject/resource/action search, and discovery. Every malformed request is 400; a request is read from a JSON object only. Search returns every result in one page — pagination is optional in the spec and not implemented. Not put through the OpenID Foundation certification program.
decision-subjectdraft-aravind, IETF OAuth Records the party a decision is taken upon as a pseudonymous handle, distinct from who asked and who answers. Stripped before the kernel runs, so it is recorded and never decides; a handle containing an address is refused. Authored by the maintainer. Resolving a handle to a person is out of scope.

Two more contestability profiles decern implements are described on the home page: operator-of-record (who is answerable) and the Subject-Side Access Challenge Profile, S-ARAP (how a decision is contested).

Caller postures

How a deployment establishes who is asking. decern verifies all of these itself, against keys configured at startup, never fetched.

RFC 9068bearer access tokens Validates access tokens in the §4 order: typ, alg before any key, iss, aud, signature, exp/nbf. All §2.2 required claims present. Verifies EdDSA only, so it applies RFC 9068's checks without being a conforming RFC 9068 resource server — §2.1 requires RS256, which the supply-chain gate refuses. Put the provider in front.
RFC 9421HTTP message signatures Verifies the signed-request and AAuth signature profiles: Ed25519, created-window checks, covered components fixed per profile, and a verifier that refuses any parameter it does not implement. Verification only; decern issues no signatures. No nonce cache, so a verbatim replay verifies again inside the created window.
SPIFFE JWT-SVIDworkload identity Verifies a JWT-SVID against a JWK Set pinned at startup; trust domains match exactly; the JOSE header is closed to alg/kid/typ. ES256 only. RS*/PS* need a crate carrying an unpatched advisory the supply-chain gate refuses; EdDSA is outside the SVID's closed algorithm set. Federation and the Workload API are not implemented.
AAuthdraft-hardt -11, agent tokens The resource half of agent identity access: verifies an aa-agent+jwt and its §11.3 signature profile for Ed25519, pins providers, and binds a verified agent to itself. An individual Internet-Draft, not working-group adopted. Refusals other than clock skew carry no Signature-Error; ES256 is not verified; providers are configured, not discovered. Each departure is named in the registry.
Signature-Keydraft-hardt Carries the token that binds the signing key, as a covered component of the outer signature. —
OAuth 2.1draft-ietf -15 The protected-resource half only: bearer presentation and the 401/403 error responses with their challenges. decern is not an authorization server and implements none of the grant machinery.
RFC 6750 · RFC 8707bearer usage, resource indicators The Authorization: Bearer header is the only accepted presentation; every refusal carries a WWW-Authenticate challenge; aud must contain the configured resource identifier, matched exactly. The form-encoded and query carriers are deliberately not implemented.

Tokens and signatures

RFC 7515 · RFC 7519JWS, JWT Compact JWS verified with alg checked before the signature; segments decoded through one strict JOSE reader; NumericDate and aud validation per the JWT rules. Verification only; decern issues no JWS.
RFC 9651structured field values Signature-Input, Signature and Signature-Key parsed as structured fields by a library, never by hand; a repeated label is refused before it could fold away. —
RFC 7800 · RFC 9530proof-of-possession, digest The cnf jwk names the key the request signature must be made with, so holding the token is not enough. Content-Digest is a required covered component on a bodied request; only sha-256 is accepted. Only the jwk confirmation member is implemented; jwe, kid and jku are not.

The ledger

RFC 8032Ed25519 Records, checkpoints and tree heads are Ed25519-signed. Every verification uses the strict check, which rejects the small-order keys the permissive equation admits. —
RFC 9162Certificate Transparency 2.0 The Merkle tree and its inclusion proofs, over leaves that are the per-record chain hashes, with leaf/node domain separation. Only the tree and its proofs are taken from the RFC. decern is not a certificate log and issues no SCTs.
RFC 8785JSON Canonicalization Every digest is a SHA-256 over a JCS canonical form, so any conformant implementation computes the same digest from the same value. —

Policy and proof

Cedarpolicy language The policy, schema and entities are Cedar; the engine is exact-pinned. —
cedar-policy-symccsymbolic compiler Compiles the Cedar model to SMT — the Lean-verified symbolic compiler — and the nine invariants are discharged as policy subsumption. The "proven" claim rests on this crate, so it is exact-pinned. —
cvc5SMT solver Discharges the proof obligations. decern prove fails closed if it is absent or a proof does not hold. —

Delegation, and the examples

RFC 8693token exchange The delegation model: an attenuated child credential is minted from a delegator's, narrowed to the scopes it holds and capped at its expiry, so a child can never exceed its parent. The wire protocol is not implemented — there is no /token endpoint. What decern takes is the delegation model, not the HTTP surface.
Model Context ProtocolMCP A stateless Streamable-HTTP server that consults decern before every tool call, with the authorization-failure layering the spec assigns. Implemented only in examples/mcp — decern's crates carry no MCP surface.
Forward-authNGINX / Traefik / Envoy The shared subrequest contract: 200 allows, 403 denies, 503 when no decision could be obtained. Implemented only in examples/ext_authz_adapter — decern's crates carry no gateway surface.

The standards registry carries the full conformance text and the date each specification was last read: .agent/standards/registry.yaml. Each release also states what it does not claim, in known limits.
